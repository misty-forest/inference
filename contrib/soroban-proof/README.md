# Symbolic Soroban scenarios for Inference

`infs-soroban-prove CONTRACT.wasm PROPERTIES.inf` checks stateful `forall` scenarios against the instructions of a compiled contract. The [single-method demo](https://github.com/misty-forest/inference-formal-demo) includes a Rust contract, its public Wasm and the two properties. Contract authors write assertions and choose the ledger and authorization assumptions in the spec.

## Install

Use Python 3.10+, WABT (`wasm2wat`), Stellar CLI 27 and [infc 0.0.6](https://github.com/Inferara/inference/releases/tag/v0.0.6). From this checkout:

```sh
python3 -m venv /tmp/infs-proof-env
. /tmp/infs-proof-env/bin/activate
python -m pip install ./contrib/soroban-proof
```

The Python package installs Z3. Put `infc` on PATH or set `INFC_PATH`. All commands use local Wasm files.

## Where the functions come from

| Expression in a spec | Implementation |
| --- | --- |
| `create_lock(...)` | Generated from the artifact's embedded Stellar contract spec. Dispatches its real Wasm export with encoded Soroban arguments. |
| `authorize_create_lock(...)` | Generated from the same ABI. Installs an owner grant for the named invocation and exact typed arguments. |
| `try_create_lock(...)` | Invokes the same export. A modeled trap rolls back token balances and storage before returning false. An unsupported operation instead aborts verification. |
| `funded_ledger(now, amount)` | Starts a fresh ledger with the owner holding the symbolic amount, the locker holding zero and empty contract storage. |
| `allow_transfer(OWNER, LOCKER, amount)` | Adds the standard asset transfer as a child of the owner grant. `auth_consumed()` reads which nodes actually authorized a call. |
| `balance_u64(address)` | Checked read of the modeled asset's signed 128-bit balance. A balance outside the unsigned 64-bit range traps. |
| `stored_u64(a, b, field("amount"))` | Looks up the persistent key `(a,b)` and decodes the named field from the map actually written by Wasm. A missing field or key fails the assertion path. |

The temporary Inference host declarations are generated by [the frontend](soroban_proof/prove.py). Their implementations live in [the ledger model](soroban_proof/ledger.py). For example, the Wasm host call for an asset transfer decodes the contract's transfer vector, checks the grant and available funds, and updates two balances. The observer reads those updated balances. Storage keys and map values are decoded from the Wasm's memory and host calls.

## What PROVED means

The fork supplies a separate Z3 backend for a restricted, imperative `spec … forall` dialect. The frontend type-checks the expanded spec with `infc`, lowers its leading scalar assumptions and assertions into executable Inference functions, and compiles those with `infc`. The [symbolic interpreter](soroban_proof/engine.py) executes both that Wasm and the supplied contract Wasm. Each quantified unsigned integer is a full-width bitvector; a bool ranges over false and true. Each conditional explores all feasible outcomes under accumulated Z3 constraints. The report counts symbolic paths, each of which can represent many inputs.

A successful result requires at least one admissible path, assertions on every admitted path, and exhaustion of the worklist. A failing path produces a model with concrete inputs. Unknown solver results, unsupported semantics and exploration limits terminate with an inconclusive result. Exit codes are 0 for all properties proved, 1 for a counterexample and 2 for inconclusive. This backend produces solver results, without a Rocq proof certificate.

## Model scope and trust

The profile covers the protocol 29 host calls used by the demo. Each scenario has one invocation on a fresh ledger, distinct owner/token/locker identities, and a standard Stellar asset. The owner is a funded non-issuer with an authorized, unrestricted token balance. The host model enforces one owner grant with an optional nested transfer, transaction atomicity, a ledger clock, address-vector keys, and symbol-keyed records of u64 fields. The ABI generator currently accepts address/u64 arguments and void results.

The claims assume valid credentials for installed grants, live ledger entries, sufficient execution resources and standard token transfer semantics. Real signatures, signer contracts, arbitrary token code, fees, TTL changes, resource exhaustion and reentrancy are outside this model. The handwritten host and Wasm interpreter are part of the trusted implementation. They have not been formally validated against the Stellar host. The path and instruction limits produce an inconclusive result if exhausted.

Run the focused interpreter regressions from this directory with `python -m unittest discover -s tests`. They also require WABT's `wat2wasm`.

With the CLI installed and the public demo checked out, run `python tests/check_demo.py /path/to/inference-formal-demo` to rebuild a Rust mutation. The mutation stores zero only when the input is `u64::MAX`. The script requires the original properties to pass and the unchanged spec to find that precise counterexample in the compiled mutant.
